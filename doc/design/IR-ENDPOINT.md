# ESP32 IR endpoint

Status: implemented in `firmware/esp32` and verified in host simulation and
target compilation. Hardware acceptance is **NOT RUN**; every pin, polarity
and timing claim about silicon below is ⚠ bench-unverified. See
[ADR 0025](../decisions/0025-esp32-rmt-ir-endpoint-itach-subset.md) and
[ADR 0026](../decisions/0026-esp32-endpoint-health-recovery-and-storage.md).

The endpoint is the ADR 0019 ESP32-S3 + W5500 PoE firmware with IR added.
IR is generated by the RMT peripheral: one TX channel per IR connector, a
hardware carrier, and a mark/space timeline at 1 µs resolution. Controllers
reach it through a subset of the Global Caché
[iTach API v1.5](https://www.globalcache.com/files/docs/API-iTach.pdf) on
TCP 4998. Administration and firmware updates stay on the mutual-TLS HTTPS
API in [ESP32-UPDATES.md](ESP32-UPDATES.md).

## Protocol subset

Requests are ASCII lines ended by CR. LF is ignored, so CRLF clients work,
and empty lines are ignored. Responses end with CR, as in the specification.
Commands are case-sensitive. IR connectors are `1:1` to `1:N`, where N is
`CONFIG_YOKE_IR_OUTPUTS` (1-4). Module 0 is the Ethernet module.

| Request | Response |
|---|---|
| `getdevices` | `device,0,0 ETHERNET`, `device,1,<N> IR`, `endlistdevices` |
| `getversion` | `Make=Yoke;Model=yoke-ir;Revision=<app version>` |
| `getversion,0` / `getversion,1` | `version,<m>,<same identity>` |
| `sendir,1:<c>,<id>,<freq>,<repeat>,<offset>,<on1>,<off1>,...` | `completeir,1:<c>,<id>` after the last frame has left the pin |
| `stopir,1:<c>` | `stopir,1:<c>`, always, also to the owner if it differs |
| `get_IRL` | `IR Learner Enabled` or `IR Learner Unavailable` |
| `stop_IRL` | `IR Learner Disabled` |
| anything else | `ERR_01` |

`sendir` accepts frequency 15000-500000 Hz, repeat 1-50, an odd offset 1-383
that addresses an on-duration inside the pattern, and 1-260 on/off pairs of
1-65535 carrier cycles. The compressed form is accepted: the first 15 unique
pairs become `A`-`O` and may replace a pair anywhere a pair may start.
The first transmission sends the whole pattern. Each further repeat sends it
from `<offset>`, so a preamble is sent once.

Errors use the specification's format. Address errors report `0:0`:
`ERR_0:0,002` for a module other than 1, `ERR_0:0,003` for an unknown
connector and `ERR_0:0,017` for an unparsable address. Other `sendir` errors
report the connector: 004 ID, 005 frequency, 006 repeat 0, 012 repeat above
50, 007 offset, 008 no pulses, 009 bad pulse value or a frame above the
duration bound, 010 an odd number of durations, 020 more than 260 pairs, 021
a symbol in an off position, 022 an undefined symbol, and 019 when the RMT
driver refuses a transmission. Line errors are `ERR_15` (no CR before the
4096-byte buffer filled; input is discarded up to the next CR) and `ERR_11`
(a partial line older than 10 s).

### Ownership, busy, stop and smooth repeat

- A connector transmitting for connection A answers `busyIR,1:<c>,<id>` to a
  `sendir` from any other connection. Connectors are independent.
- An **identical** `sendir` from A (same ID, frequency, repeat, offset and
  durations, compressed or not) resets the remaining repeat count to
  `<repeat>`. It is acknowledged by the single `completeir` of the
  transmission it extended. If the encoder has already ended the stream, the
  command is queued as a new transmission, as the specification describes;
  further identical commands fold into that queued one.
- A **different** `sendir` from A halts the current transmission at its next
  frame boundary (that transmission still gets its `completeir`) and runs
  next. A third command while one is queued gets `busyIR`.
- `stopir` cuts the output immediately, discards repeats and any queued
  command, and the owner receives `stopir` instead of `completeir`.
- If the owner disconnects, its transmission finishes its bounded remaining
  repeats and nobody is told. A queued command from it is dropped.
- After the last identical command, at most `repeat + 1` frames start: the
  RMT channel memory lets the encoder decide one frame ahead. The final gap
  of each frame is spread across enough symbols that the decision falls
  inside that gap while the frame is on the pin.

### Learning

Learning is off unless enabled in NVS and a learning input is configured
(`CONFIG_YOKE_IR_LEARN_GPIO`). A wideband sensor that passes the carrier
yields the measured frequency and exact per-burst cycle counts. A
demodulating receiver yields the envelope only, so 38 kHz is assumed. The
captured code is sent once to the learning connection as an uncompressed
`sendir,1:1,0,<freq>,1,1,...` line. The final off-time is not observable and
is reported as 50 ms. Only one connection learns at a time. Learning ends
with `stop_IRL`, with any other command from that connection, or after 60 s
(`IR Learner Disabled` is sent).

### Deliberate deviations from iTach units

No AMXB discovery beacon, no `get_NET`/`get_IR`/`set_IR`/serial/relay
commands (`ERR_01`), only module 1, repeat above 50 rejected rather than
clamped, a queue depth of one per connector, and learning ends only on
commands from the learning connection (iTach ends it on any command from any
connection, which a polling controller would trigger constantly).

## Limits and bounds

| Bound | Default | Where |
|---|---|---|
| Connections | 4 (max 8); when full, the longest-idle (≥ 30 s) connection holding nothing is evicted, else the new one is refused | `CONFIG_YOKE_IR_MAX_CONNECTIONS` |
| Command rate | 20 lines/s sustained, burst 40, per connection; excess lines wait (TCP backpressure), they are not dropped | `CONFIG_YOKE_IR_RATE_PER_S`, `_BURST` |
| Line length | 4096 bytes including CR (the largest valid `sendir` is about 3.2 KB) | `IR_LINE_MAX` |
| Output buffer | 4096 bytes; a client that stops reading is closed after 10 s without progress | `IR_OUT_MAX` |
| Frame duration | 2 s per frame (Thermite's bound for a whole code is 2 s), 512 RMT symbols | `CONFIG_YOKE_IR_MAX_FRAME_MS` |
| Transmission | ≤ 50 frames unless refreshed by identical commands | iTach rule |
| Learning session | 60 s; 4096 RX symbols per capture, 20 ms silence ends it | `ir_rmt.c` |

Memory: about 3.1 KB per program, two programs per connector plus one for
parsing, and 8 KB per connection, allocated once at boot.

## Security posture

The iTach API has no authentication or encryption, and Yoke keeps that for
compatibility. Anyone who can reach TCP 4998 can send IR. Mitigations:

- **Off by default.** `CONFIG_YOKE_IR_API_DEFAULT=n`. The NVS key
  `yoke_ir/api` overrides it. That key is changed only through
  `PUT /v1/ir/config` on the mutual-TLS admin API, or by USB provisioning.
- **LAN-scoped.** A peer must be inside the interface's IPv4 subnet, or
  inside an explicit allowlist (`"allow": "192.168.20.0/24"`). Others are
  closed on accept. Scope is enforced for the life of the connection: it is
  re-checked every second and on any settings change, so a narrowed
  allowlist or a changed or lost address drops admitted peers. A stored
  allowlist that cannot be parsed refuses everyone.
- **Bounded.** Rate, connection, line, buffer, frame and learning limits
  above. The listener runs in its own task above the HTTPS server's
  priority, so a dribbled TLS handshake cannot stall IR. The task is pinned
  to CPU0 with the RMT interrupts, so stopping a channel never races its
  ISR on the other core. IR work per wakeup is bounded and the task is
  watched by the task watchdog.
- **Panics stay quiet.** A panic would otherwise leave RMT replaying its
  channel memory, carrier included, while the core dump is written. A
  wrapper around `esp_panic_handler` first detaches every IR pin from RMT
  and holds it at the idle level. It is IRAM-resident, and `verify.py`
  checks that from the link map.
- **No escalation.** Port 4998 cannot change settings, firmware, trust or
  learning, and it reveals only the identity string. Learning is off by
  default and can be enabled only by the administrator.

```sh
curl --fail-with-body --noproxy '*' --resolve ir-01.local:443:192.168.20.50 \
  --cacert .scratch/esp32-ota/trust/ir-01/server.crt \
  --cert .scratch/esp32-ota/trust/ir-01/client.crt \
  --key .scratch/esp32-ota/trust/ir-01/client.key \
  -H 'Content-Type: application/json' -X PUT \
  --data '{"api": true, "learning": false, "allow": "192.168.20.0/24"}' \
  https://ir-01.local/v1/ir/config
```

Fields are optional, unknown fields are rejected, settings persist in NVS
and apply immediately (disabling the API closes the listener and its
connections). An empty `allow` returns to subnet scope.

## Pins and hardware (⚠ bench-unverified)

| Kconfig | Default | Role |
|---|---|---|
| `YOKE_IR_GPIO_1`..`_4` | 15, 16, 17, 18 | Emitter driver input for connectors 1:1-1:4 |
| `YOKE_IR_INVERT` | n | Set for an active-low emitter driver |
| `YOKE_IR_DUTY_PERCENT` | 33 | Carrier duty |
| `YOKE_IR_LEARN_GPIO` | -1 | Learning sensor output (none) |
| `YOKE_IR_SELFTEST_LOOPBACK` | y | Boot loopback on the 1:1 pin |

The defaults avoid the W5500 pins (9-14), USB (19, 20), strapping pins (0, 3,
45, 46) and flash/PSRAM pins. They have not been checked against the
Waveshare ESP32-S3-ETH header. A GPIO cannot drive an IR LED directly: use a
transistor or MOSFET driver sized for the LED current. Carrier frequencies
come from an integer divider of the 80 MHz APB clock (38 kHz → 38004.75 Hz,
36 kHz → 36003.6 Hz, 56 kHz → 56022.4 Hz). At boot, the self-test runs the
parser, compiler and the IRAM encoder against a known NEC frame. It then
loops three unmodulated pulses (40-120 µs) from the 1:1 pin into an RX
channel. Without a carrier, no IR receiver decodes them. A failure rolls
back a pending image and disables IR on a confirmed one.

## Host simulation (software only)

`tests/firmware_ir` compiles `ir_core.c`, `ir_program.c` and `ir_encode.c`
unchanged. `host_ir_server.c` puts them behind real localhost TCP sockets,
with a virtual clock and a model of each RMT channel. The model is a
48-symbol memory, filled when a transaction starts and refilled 24 symbols
at a time by the target encoder function, with carrier ticks computed as
ESP-IDF does. pytest drives it. The tests cover:

- Protocol, specification examples, every error code, framing, CRLF,
  oversized lines and partial-line timeouts.
- Busy across connections, `stopir`, smooth repeat (reset, too late, bound
  after release), replacement by a new command, quiesce, and disconnect
  mid-send.
- Rate limiting, slow readers, connection limits and eviction, and LAN-scope
  refusal.
- Exact waveforms for NEC, RC5 and a Pronto-converted Sony SIRC code at 36,
  38, 40 and 56 kHz. Every edge is within half a tick of `N/f`, the carrier
  is within 0.05 %, and each code decodes to its address and command.
- A learning round trip from a raw carrier capture and from a demodulated
  envelope.
- Thermite iTach stand-in transcripts and every boundary of Thermite's
  profile rules (copied as data in `fixtures/thermite_itach.json`).
- Host CPU cost.

`make firmware-bench` prints the host cost. These numbers say nothing about
ESP32-S3 timing.

The simulation cannot show GPIO routing, emitter drive, real carrier phase
(the model assumes the carrier restarts at each mark), ISR latency, cache
behaviour during flash writes, or W5500 throughput.

## Bench procedure — NOT RUN

Use a scope or logic analyser on the emitter driver input and, separately,
a reference IR receiver and a known device. Record firmware version and
settings. Each item is ⚠ until it passes.

1. **Carrier accuracy.** For 36, 38, 40 and 56 kHz, measure frequency and
   duty over at least 100 periods. Expect within 0.1 % of the values above
   and 33 % ± 2 %. Check that the line idles low (or high with
   `YOKE_IR_INVERT`) before, between and after frames, and after `stopir`.
2. **Timing.** Send the NEC, RC5 and SIRC codes from the host tests.
   Mark/space edges must be within ±2 µs of `N/f` across a whole frame (no
   drift). Check whether each mark starts on a carrier phase boundary,
   because the host model assumes it does. Repeats must start at
   `<offset>`, and `completeir` must arrive only after the last falling
   edge.
3. **Smooth repeat.** Hold a volume key from a controller (identical
   `sendir` every 100 ms, repeat 2). Release it. Count frames after the last
   command: at most 3.
4. **TCP load.** With four connections sending at the rate limit and a fifth
   connecting, verify `busyIR`, refusal or eviction, and that the waveform
   on an idle connector is unaffected. Run an unauthorised-subnet peer and
   confirm refusal.
5. **IR during OTA.** Start a repeating `sendir` (repeat 50) and upload
   firmware over HTTPS. The waveform must have no gaps, stretched marks or
   stuck carrier while flash is erased and written. After 202, the reboot
   must wait for the frame in flight (watch the pin and serial log).
6. **Dribbled handshake vs watchdog.** Dribble a TLS ClientHello one byte
   every 30 ms to port 443. Confirm the handshake is dropped at 10 s, IR on
   port 4998 keeps responding, and no task-watchdog reset occurs. Then
   suspend the HTTPS task in a debug build and confirm a task-watchdog panic
   leaves `coredump_present: true` and `reset_reason: task-watchdog`.
7. **Learning** (if a sensor is fitted): learn NEC, RC5 and a 56 kHz code,
   replay each, and confirm the device responds. Check that the reported
   frequency is within 1 %.
8. **Boot self-test.** Confirm the loopback passes with the emitter
   connected and that no nearby device reacts to the boot pulses.
