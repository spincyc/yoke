# Cold review and dispositions (2026-11-04)

Status: independent cold reviews run on 2026-11-04, covering the USB
software, the ESP32 firmware, IR over TCP/IP, the chipsets and the
housing. This page records each consequential finding and what became of
it, so a later session does not re-derive or re-raise a settled point
without new evidence. Chipset and power evidence is in
[CHIPSETS.md](CHIPSETS.md).

Dispositions: **fixed** (with its regression test), **accepted** (a
deliberate limit, recorded) or **open**.

## Starting point

- `make verify` passed (1736 tests), yet no code presented a remote
  device through the computer-side box's USB port. The consumer ran
  `usbip attach` into the box's own kernel, so a remote keyboard typed into
  the box rather than the user's computer.
- About 11k of the 16.7k source lines were off the USB critical path
  (media, telemetry, updater, ESP32 OTA).
- No IR transport existed anywhere in Yoke.

## USB data path

| Finding | Disposition |
|---|---|
| No computer-side gadget presentation | **Fixed:** userspace USB/IP client plus Raw Gadget worker, ADRs 0021/0022, `tests/usbsim`, `make verify-usb-kernel` |
| Raw Gadget bound with the device name (`fcc00000.usb`) instead of the UDC driver name (`dwc3-gadget`); RUN would fail with EBUSY on the RK3566 | **Fixed**, found by the second cold review. The worker infers the driver name from sysfs; the fake UDC now rejects a wrong name |
| SIGUSR1/EINTR cancellation was dead: CPython `fcntl.ioctl` retries EINTR off the main thread (PEP 475), so teardown never confirmed | **Fixed:** ctypes ioctl called once. The VM negative control proves the old path cannot cancel |
| dwc3 returns -EPIPE on started requests after a host CLEAR_FEATURE(HALT); pumps died | **Fixed:** treated as a cleared halt; modelled in the fake's dwc3-strict mode |
| Stock stub orders RET_SUBMIT before RET_UNLINK; a late RET_SUBMIT dropped the connection | **Fixed:** unlink tombstones |
| Remote STALL spin (about 53k CMD_SUBMIT/s) | **Fixed:** one clear per local halt, bounded backoff |
| Zero-length control IN sent as DIR_IN (kernel "BOGUS control dir" WARN) | **Fixed** |
| Control OUT with data is acknowledged before the remote answers, so a remote STALL of SET_REPORT or SET_LINE_CODING reaches the host as success | **Accepted:** a Raw Gadget limit, documented per class in `USB-DATAPATH.md` |
| The simulation encoded the same wrong kernel assumptions as the code | **Fixed:** the fake now has per-UDC names, dwc3 disconnect/EPIPE/late-ep0 behaviour, stub bad-endpoint desync and advisory host deadlines. A real-kernel QEMU loopback ran 8 MiB checksummed I/O at 480M, detach, remote loss and a usbipd restart |

## Control plane (YWP/1)

| Finding | Disposition |
|---|---|
| Wall-clock offset captured once at startup; an agent started before NTP dropped peers as stale for its whole uptime | **Fixed:** ADR 0023, re-read per frame |
| Sequence floor = max(saved, wall); a far-future boot muted the node | **Fixed:** 60 s cap plus `yoke agent --rebase-sequence` |
| Canonical encoding defined by a Python call; third-party number formatting failed auth | **Fixed:** MAC over transmitted bytes, legacy form still accepted, 27 vectors |
| USB/IP recovery wedge beside an unrelated record-less port | **Fixed:** journal schema 3, ADR 0024 |
| No local logging | **Fixed** |
| Shipped unit could not run usbip | **Fixed:** root-owned single-purpose units, `packaging/zero3e/` |
| USB/IP data plane open to any LAN host | **Fixed** in part: producer admission from authenticated consumer claims (nftables ⚠). **Accepted:** it trusts the source IPv4 and the payload is unencrypted |
| Site-wide PSK: any key holder can author intents | **Accepted / open:** needs a YWP/2 identity design |
| Slow re-attach after replug; `usbip list` every second; silent open mode; spec drift | **Fixed** |

## ESP32 firmware and IR

| Finding | Disposition |
|---|---|
| New image confirmed healthy before link or IP, so a broken image could not roll back | **Fixed:** ADR 0026 health gating |
| No retry or restart after a confirmed image failed at boot | **Fixed** |
| Unversioned journal; no coredump or IR storage; no task-watchdog panic; thin status | **Fixed:** 0.2.0 partition table needs one USB reflash |
| OTA flash writes versus RMT; reboot could cut an IR frame | **Fixed:** cache-safe RMT and a restart guard |
| Device key in plaintext flash; no secure boot | **Accepted for now:** path recorded in ADR 0026 |
| IR placement | **Decided:** ESP32 RMT endpoint with an opt-in iTach subset on 4998 (ADR 0025). Not Radxa `pwm-ir-tx`, not the Mega |

## Housing

**R6 (89 × 45.5 × 46 mm) was too large, as the owner observed.** Against
the official board + HAT envelope of 71.5 × 31.5 × 37.0 mm, the gaps were:

| Location | Gap | Cause |
|---|---|---|
| Closed end | 12.7 mm | case-screw bosses |
| USB side | 7.5 mm | clip boss; USB-C faces 9.5 mm inside the wall |
| Above the HAT | 3.5 mm | roof allowance |

**R7.**
- PoE box 81.4 × 36.25 × 41.7 mm (34% less volume); bare computer-side
  box 81.4 × 36.25 × 18.5 mm; USB-C faces 2.15 mm from the wall.
- Its first independent review **failed**: the case-screw spigots were
  joined to the base by one unbridged 0.2 mm layer, with 3.09 mm² stops.
- Fused post rings over real slicer bridges, with 29.3 mm² seats, passed
  the second review. Printed 2026-11-04 (`hardware/usb-housing/r7/print.json`).
- Physical fit and cooling are NOT RUN.

## Open items

  RK3566, the UDC endpoint budget, computer-side current draw, IR timing
  on silicon and R7 fit. See [CHIPSETS.md](CHIPSETS.md#bench-tests-that-decide).
- **Generic bulk OUT without a class hint** moves one packet per URB.
- **Thermite** needs a model allowance to drive a Yoke IR endpoint.
- **YWP/2** per-device identity and authorization.
